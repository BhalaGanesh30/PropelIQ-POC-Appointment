# User Story - US_034

## Story ID
* ID: US_034

## Story Title
* Scheduling Override with Mandatory Audit

## Description
* As a staff member, I want to override scheduling constraints (such as cancellations within 24 hours) with mandatory reason capture so that exceptional situations are handled while maintaining a full audit record.

## Acceptance Criteria
1. **Given** a scheduling constraint blocks an action (e.g., cancellation within 24 hours), **When** a staff member with override privileges invokes the override, **Then** a mandatory reason dialog is shown before the action can proceed.
2. **Given** the staff member provides a reason and confirms the override, **When** the override is processed, **Then** the scheduling action is completed and an audit record is created capturing the staff member's identity, the overridden constraint, the reason, and the timestamp.
3. **Given** an override is attempted without providing a reason, **When** the staff member submits without filling the reason field, **Then** the system validates and displays "Override reason is required" and does not proceed.
4. **Given** an admin reviews the audit log, **When** they filter by action type "Override," **Then** all override events are listed with full reason and actor details.

## Edge Cases
* What happens if the override reason exceeds the maximum character limit? (Validation error is shown; reason field is capped at 500 characters with a character counter.)
* How does the system handle override attempts by a Patient role? (Patient role does not have override privileges; the override option is not rendered; API enforces HTTP 403 if called directly.)
