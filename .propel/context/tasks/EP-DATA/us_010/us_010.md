# User Story - US_010

## Story ID
* ID: US_010

## Story Title
* Referential Integrity and Append-Only Audit Tables

## Description
* As a developer, I want referential integrity constraints and append-only write restrictions on the audit table so that data consistency and immutable audit evidence are enforced at the database layer.

## Acceptance Criteria
1. **Given** the schema is applied, **When** an attempt is made to insert an Appointment record with a non-existent PatientId, **Then** the database rejects the insert with a foreign key violation error.
2. **Given** transactional operations are executed (booking, arrival, waitlist swap, coding finalization), **When** a partial operation fails mid-transaction, **Then** the entire transaction rolls back and no partial data is persisted.
3. **Given** the AuditRecord table is created, **When** a database role attempts to execute UPDATE or DELETE on the AuditRecord table, **Then** the operation is rejected by a write-restriction policy or row-level security rule.
4. **Given** a new audit event is written, **When** the INSERT succeeds, **Then** the record is immutable and its content matches the structured schema defined for audit events.

## Edge Cases
* What happens if a bulk import violates referential integrity mid-batch? (Transaction rolls back entire batch; error report identifies the offending rows.)
* How does the system handle attempts to bypass audit restrictions via DBA access? (Audit table access is logged at the connection level; privileged access requires documented change-control approval.)
