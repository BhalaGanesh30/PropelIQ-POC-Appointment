# User Story - US_047

## Story ID
* ID: US_047

## Story Title
* Authorized Data Editing and Verification

## Description
* As a clinician or authorized staff member, I want to edit and verify extracted clinical data with an immutable audit trail so that inaccurate extractions can be corrected while maintaining a full history of changes.

## Acceptance Criteria
1. **Given** I am an authorized clinician, **When** I edit an extracted clinical fact (e.g., correct a medication name), **Then** the change is saved, the fact's verification state is updated to "Verified," and the previous value is recorded in the audit trail.
2. **Given** I verify an extracted fact without changes, **When** I mark it as "Verified," **Then** the verification state is updated and the reviewer's identity and timestamp are stored.
3. **Given** an audit trail exists for a clinical fact, **When** I view the fact's history, **Then** all previous values, editors, and timestamps are displayed in chronological order.
4. **Given** a patient role attempts to edit a clinical fact, **When** the edit request is submitted, **Then** the API returns HTTP 403 and no change is persisted.

## Edge Cases
* What happens if two clinicians edit the same fact simultaneously? (Optimistic concurrency control detects the conflict; the second writer receives a conflict error and is shown the current value to retry with.)
* How does the system handle edits to facts that are referenced by coding decisions? (Edit is allowed; a warning is shown: "This fact is referenced by a coding decision. Review the coding decision after saving.")
