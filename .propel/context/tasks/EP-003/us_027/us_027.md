# User Story - US_027

## Story ID
* ID: US_027

## Story Title
* Multi-Channel Reminder Delivery via Email and SMS

## Description
* As a patient, I want appointment reminders delivered via email (SendGrid) and SMS (Twilio) with one-click confirmation and cancellation links so that I can confirm or cancel my appointment directly from the reminder.

## Acceptance Criteria
1. **Given** a reminder event is dispatched, **When** the patient's preferred channel is email, **Then** a formatted reminder email is sent via SendGrid containing appointment details, a one-click confirm button, and a one-click cancel link.
2. **Given** a reminder event is dispatched, **When** the patient's preferred channel is SMS, **Then** a concise reminder SMS is sent via Twilio containing appointment time and a short-link for confirmation or cancellation.
3. **Given** a patient clicks the confirm link in a reminder, **When** the confirmation request is processed, **Then** the appointment status is updated to "Patient Confirmed" and the event is recorded.
4. **Given** a reminder delivery fails (provider error or unreachable), **When** the failure is detected, **Then** the system retries up to 3 times with exponential backoff and moves the event to a dead-letter queue after all retries fail.

## Edge Cases
* What happens if a patient clicks a confirmation link after the appointment has passed? (The link is expired; the response page informs the patient the action is no longer applicable.)
* How does the system handle Twilio SMS rate limiting? (Messages are queued and dispatched within provider rate limits; urgent same-day reminders are prioritized.)
