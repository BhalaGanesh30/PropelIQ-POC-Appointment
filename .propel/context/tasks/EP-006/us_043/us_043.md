# User Story - US_043

## Story ID
* ID: US_043

## Story Title
* Document Categorization, Rename, and Soft-Delete

## Description
* As a clinician or staff member, I want to categorize, rename, and soft-delete clinical documents so that patient document libraries are organized and recoverable if accidentally removed.

## Acceptance Criteria
1. **Given** I have access to a patient's document list, **When** I assign a category to a document (e.g., Lab Report, Referral, Prescription), **Then** the category is saved and the document list updates to show the assigned category label.
2. **Given** I view a document in the document list, **When** I rename it, **Then** the display name is updated immediately in the UI and persisted to the database, while the original storage filename is preserved.
3. **Given** I want to remove a document from view, **When** I soft-delete a document (after confirming the confirmation dialog), **Then** the document is hidden from the active list but remains in the database with `IsDeleted = true`.
4. **Given** I am an admin reviewing soft-deleted documents, **When** I access the document trash view, **Then** all soft-deleted documents are listed with their deletion date and I can restore them.

## Edge Cases
* What happens if I try to categorize a document that is still processing (OCR in progress)? (Categorization is allowed; the category is saved; OCR completion does not override the category.)
* How does the system prevent hard deletion? (Hard delete is not exposed in any UI or API for clinical documents; only soft-delete is permitted; physical deletion requires a separate archival policy trigger.)
