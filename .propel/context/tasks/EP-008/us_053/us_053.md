# User Story - US_053

## Story ID
* ID: US_053

## Story Title
* AI Gateway Integration with Circuit Breaker Fallback

## Description
* As a developer, I want the AI coding and extraction requests routed through the AI gateway with circuit-breaker fallback to manual flows so that the system degrades gracefully when the AI provider is unavailable.

## Acceptance Criteria
1. **Given** the AI gateway is healthy, **When** a coding suggestion request is sent, **Then** the request is routed to the configured AI provider and a response is returned within 2.5 seconds p95.
2. **Given** the AI provider returns errors for 5 consecutive requests within 60 seconds, **When** the circuit breaker threshold is reached, **Then** the circuit opens and all subsequent AI requests immediately return a fallback response prompting manual workflow.
3. **Given** the circuit breaker is open, **When** a half-open probe succeeds after the recovery window, **Then** the circuit closes and AI-assisted requests resume normally.
4. **Given** an AI request exceeds the configured timeout, **When** the timeout fires, **Then** the gateway cancels the request, logs the latency breach, and returns the manual coding fallback response.

## Edge Cases
* What happens if the circuit breaker toggles rapidly between open and closed? (A minimum hold-open time prevents rapid cycling; operations team is alerted after 3 circuit trips within an hour.)
* How does the system inform the user when AI fallback is active? (A notification banner reads "AI assistance temporarily unavailable. Manual coding mode is active." on all AI-dependent screens.)
