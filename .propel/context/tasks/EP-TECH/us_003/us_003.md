# User Story - US_003

## Story ID
* ID: US_003

## Story Title
* PostgreSQL and pgvector Database Provisioning

## Description
* As a developer, I want a provisioned PostgreSQL 15 database with the pgvector extension enabled so that the system has a fully functional primary datastore ready for entity migration and vector retrieval workloads.

## Acceptance Criteria
1. **Given** the Docker Compose stack is started, **When** the PostgreSQL 15 container initializes, **Then** the database is accessible on the configured port with the application credentials.
2. **Given** the PostgreSQL instance is running, **When** `CREATE EXTENSION IF NOT EXISTS vector;` is executed, **Then** the pgvector extension is active and `SELECT * FROM pg_extension WHERE extname = 'vector'` returns a row.
3. **Given** the database is provisioned, **When** Entity Framework Core migrations are run with `dotnet ef database update`, **Then** all migrations apply without error and the schema matches the defined entities.
4. **Given** the application is connected to the database, **When** a test query is executed over a vector column, **Then** the query completes successfully using the pgvector operator (`<->`).

## Edge Cases
* What happens if the database port is already in use? (Docker Compose fails with a port conflict error; developer resolves by changing the port mapping in `docker-compose.yml`.)
* How does the system handle schema migration failure? (Migration rollback is supported; failed migration is reported with the exact SQL statement that failed.)
