# User Story - US_054

## Story ID
* ID: US_054

## Story Title
* PII Redaction for AI Prompts

## Description
* As a compliance officer, I want direct patient identifiers redacted from AI prompts before model invocation with redaction actions logged so that PHI is not exposed to AI model providers beyond the minimum required treatment context.

## Acceptance Criteria
1. **Given** an AI request is prepared for a coding or extraction task, **When** the prompt is constructed, **Then** the PII redaction pipeline removes direct identifiers (name, date of birth, SSN, address) and replaces them with anonymized tokens before the prompt is sent to the model.
2. **Given** a redaction action is performed, **When** the redaction completes, **Then** the redaction event is logged with the fields redacted, the anonymization tokens used, and the request correlation ID.
3. **Given** the redacted prompt is sent to the model, **When** the response is returned, **Then** de-anonymization mapping is applied to restore context references in the response without re-exposing raw PII in logs.
4. **Given** a retrieval access control filter is applied, **When** context documents are assembled for the AI prompt, **Then** only patient-specific documents authorized for the requesting clinician are included; cross-patient context is never mixed.

## Edge Cases
* What happens if the redaction pipeline fails? (The AI request is blocked; an error is returned to the caller; the failure is logged with the request ID; no raw PII reaches the model.)
* How does the system handle redaction of embedded PII in free-text clinical notes? (NLP-based entity recognition identifies PII patterns in free text and applies token substitution; a confidence threshold governs detection sensitivity.)
