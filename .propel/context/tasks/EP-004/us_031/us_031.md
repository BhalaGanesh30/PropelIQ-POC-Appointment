# User Story - US_031

## Story ID
* ID: US_031

## Story Title
* Real-Time Queue Dashboard

## Description
* As a staff member, I want a real-time queue dashboard with color-coded appointment statuses and wait-time estimates so that I can manage patient flow efficiently throughout the day.

## Acceptance Criteria
1. **Given** I am authenticated as a staff member, **When** I open the queue dashboard, **Then** all today's appointments are displayed with status badges (Waiting, In-Progress, Completed, No-Show) and wait-time estimates, rendered within 3 seconds.
2. **Given** a patient's status changes (e.g., checked in, called), **When** the status update is processed, **Then** the queue dashboard refreshes the affected patient entry within 5 seconds without a full page reload.
3. **Given** the queue is displayed, **When** a patient has been waiting longer than the estimated wait time, **Then** their entry is highlighted with a visual warning indicator.
4. **Given** I am viewing the queue, **When** I filter by appointment status, **Then** only appointments matching the selected status are shown.

## Edge Cases
* What happens if the real-time polling or WebSocket connection drops? (A reconnection attempt is made every 10 seconds; a "Reconnecting..." indicator is shown; no stale data is displayed.)
* How does the system handle a queue with 100+ patients? (Virtual scrolling is applied; only visible entries are rendered in the DOM; wait-time algorithm remains O(n) or better.)
