# User Story - US_037

## Story ID
* ID: US_037

## Story Title
* Insurance Soft Validation Engine

## Description
* As a patient completing my booking, I want my insurance details validated against format rules and a reference database without blocking my appointment so that errors are flagged early without interrupting my booking flow.

## Acceptance Criteria
1. **Given** I enter insurance details during the booking flow, **When** I submit the insurance form, **Then** the system validates the policy number format and provider code against the reference database within 500 ms.
2. **Given** the soft validation detects a format mismatch, **When** the result is returned, **Then** a warning indicator is displayed ("Insurance details may be incomplete") but the booking is not blocked.
3. **Given** the insurance details pass soft validation, **When** the form is submitted, **Then** a "Verified" status indicator is shown and the record is saved with a `SoftValidated` status flag.
4. **Given** I submit insurance details that completely fail validation, **When** the result is returned, **Then** the system flags the record with `ValidationFailed` status and records the validation result for staff review.

## Edge Cases
* What happens if the reference database is unavailable? (Validation is skipped; the booking proceeds; the insurance record is saved with `ValidationPending` status and a background retry is queued.)
* How does the system handle secondary insurance with the same policy number as primary? (Validation flags the duplicate as a potential data entry error with a warning, but does not block submission.)
