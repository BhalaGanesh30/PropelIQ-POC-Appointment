# User Story - US_019

## Story ID
* ID: US_019

## Story Title
* Appointment Slot Search

## Description
* As a patient or staff member, I want to search available appointment slots within a 30-day window by date, duration, and type so that I can find and select a suitable appointment time quickly.

## Acceptance Criteria
1. **Given** I am authenticated, **When** I submit a slot search request with date range (within 30 days), duration (15, 30, or 60 minutes), and appointment type, **Then** the system returns available slots within 1 second, sourced from Redis cache where available.
2. **Given** slot search results are returned, **When** I view the results, **Then** only future available slots are displayed; fully booked slots are excluded from results.
3. **Given** no slots match my search criteria, **When** the search completes, **Then** the system displays "No slots available" and presents the option to join the preferred-slot waitlist.
4. **Given** a date range beyond 30 days is submitted, **When** the API validates the request, **Then** the API returns HTTP 400 with a validation error message: "Slot search is limited to the next 30 days."

## Edge Cases
* What happens if a slot becomes unavailable between search and booking? (Slot reservation uses optimistic concurrency; if the slot is taken, the user is shown an updated availability view.)
* How does the system handle a Redis cache miss? (Request falls through to the database; cache is repopulated with the result and a bounded TTL.)
